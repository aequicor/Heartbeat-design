# Инструкции для прототипирования

Работай только в подрепозитории `Heartbeat-v2/design`. Выполняй команды из этого каталога и сохраняй
файлы в нём. Не используй клоны и не создавай дополнительные Git worktree.

По умолчанию работай в текущей ветке. Создавай ветки и переключайся на другие ветки только по явной
просьбе пользователя. Просьба сделать коммит или открыть PR сама по себе не разрешает создавать
или переключать ветки.

В IntelliJ IDEA открывай `Heartbeat-v2/design` через **File → Open** как самостоятельный проект.
В его окне **Commit** используется Git-привязка из `design/.idea/vcs.xml`.

1. Определи затронутые платформы и пользовательские сценарии. Зафиксируй результат оценки UI/UX в плане.
2. При создании, доработке и ревью макетов применяй [art-direction](.agents/skills/art-direction/SKILL.md).
   Если интерфейс меняется, примени скил [unslop](.agents/skills/unslop/SKILL.md) ([оригинал Дамира Соколовского](https://github.com/heydamir/unslop), CC BY 4.0). Проведи аудит по
   [списку признаков](.agents/skills/unslop/references/signs.md) и составь направление из пяти строк: продукт, характер, мир, моменты,
   сигнатура. Запиши направление в план и согласуй его с оператором до реализации.
3. Читай, редактируй и проверяй макеты в Figma через Figwright MCP. Используй компоненты
   и переменные существующей дизайн-системы.
   Выполняй проходы unslop в макете по порядку: отступы, цвет, иконки, текст, типографика, компоновка, детали.
   Для визуальной проверки используй снимок целевого кадра через Figwright MCP.
4. Покажи оператору основной сценарий и применимые состояния загрузки, отсутствия данных и ошибок.
   Укажи, где поведение различается между платформами.
5. При реализации и проверке Compose Multiplatform экранов применяй правила оформления из unslop.
   Механика HTML/CSS, снимки страниц и story-видео к Compose не переносятся.
6. Запиши согласованный вариант и прямую ссылку на кадр Figma в плане. Макет хранится в Figma.
   Изменения планов и спецификаций публикуются через PR в `Heartbeat-design`. После слияния такого PR
   передай SHA для обновления ссылки на подмодуль в Heartbeat-v2. При изменении согласованного
   сценария повторно согласуй его с оператором.

## Codex и Figwright MCP

Рабочий макет ИИ-студии — [Aurora-DS в Figma](https://www.figma.com/design/ivLmgulIBIkMzOw8sgvKxj/Aurora-DS?node-id=2-175087).
Эта ссылка ведёт на Desktop-кадр `2:175087`. Архивный `aurora-new-chat.pen` и материалы переноса
хранят историю дизайна. Текущий порядок работы задаёт этот `AGENTS.md`.

- В настольном приложении ChatGPT/Codex добавь локальный сервер `figwright` через **Settings → MCP servers → Add server**.
  Тип — `STDIO`, команда — `cmd.exe`, аргументы — `/c`, `npx.cmd`, `-y`, `@figwright/mcp@0.7.0`.
  Сохрани настройки и нажми **Restart**. Если используешь Codex CLI, эквивалентная команда в Windows —
  `codex mcp add figwright -- cmd.exe /c npx.cmd -y @figwright/mcp@0.7.0`.
  В Figma Desktop открой Aurora-DS и запусти **Plugins → Development → Figwright** на той же машине.
  Для установки плагина и диагностики используй [документацию Figwright](https://github.com/awdr74100/figwright#setup).
- Перед правками проверь подключение через `ping`, найди Aurora-DS через `list_files`, выбери его
  через `use_file` и прочитай целевой узел через `get_node`. После правок проверь структуру узла
  и сделай снимок кадра через `save_screenshots`. Если подключение не работает, укажи, на каком шаге
  возникла проблема.

Для ревью в Codex укажи ссылку на кадр Figma. Сверь его со спецификацией и планом, укажи ссылку
на соответствующий узел для каждого замечания. Для ИИ-студии Aurora начни с
[исходного референса](plans/ai-studio-reference.md) и [плана с уточнениями](plans/ai-studio-aurora.md).
