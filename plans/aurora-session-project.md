# Aurora — выбор проекта для новой сессии

Согласовано 21 ноября 2026. Проект фиксируется при первой отправке в момент успешного создания сессии. [Макет выбора проекта в Aurora-DS](https://www.figma.com/design/ivLmgulIBIkMzOw8sgvKxj/Aurora-DS?node-id=348-177375).

## Оценка UI/UX

В шапке Windows папка, название сессии «Длинная история» и шеврон входят в одну кнопку «Меню диалога» высотой 32. По такой кнопке трудно определить, какая папка выбрана и что откроется при нажатии. В дереве название проекта и название диалога уже разделены. Предлагается перенести это различие в шапку. [Исходная кнопка](https://www.figma.com/design/ivLmgulIBIkMzOw8sgvKxj/Aurora-DS?node-id=2-175598).

Аудит по списку unslop выявил проблему в подписи и назначении шеврона. Для плашки подходят существующие светлая поверхность, шрифт названий проектов Regular 14/20 и контурная папка 16. В статическом состоянии название сохраняет обычный контраст. При длинном названии сокращается текст, а шеврон остаётся видимым. На узком экране полное имя доступно в списке выбора и экранному диктору.

## Направление

- **Продукт.** Перед началом диалога человек видит, в папке какого проекта будет работать.
- **Характер.** Выбор занимает одно действие в шапке. Текст черновика остаётся перед глазами.
- **Мир.** Светлая плашка на зелёном фоне Aurora, с той же папкой, что и в навигации.
- **Моменты.** Выбор строки сразу подставляет имя проекта. После создания сессии шеврон выбора исчезает.
- **Сигнатура.** Папка и имя остаются на одном месте при переходе от черновика к сохранённому диалогу.

## Сценарий для макета

1. «Новый диалог» открывает черновик с плашкой «Без проекта». Кнопка создания в строке конкретного проекта сразу подставляет его название. В обоих случаях плашка открывает выбор.
2. В списке видны «Без проекта», знакомые проекты и действие «Открыть папку…». Текущий выбор отмечен галочкой. Например, выбор «Дизайн-система» закрывает список и обновляет плашку. Введённый текст и вложения сохраняются.
3. «Открыть папку…» вызывает системный выбор каталога. После успешного открытия плашка показывает имя папки. Отмена возвращает в черновик с прежним выбором. Если папка уже есть в списке, выбирается существующий проект.
4. При первой отправке проект фиксируется после успешного создания сессии. Пока идёт создание, повторная отправка и смена проекта заблокированы. Если сессию создать не удалось, выбор снова доступен. Если сессия уже создана, ошибка отправки или ответа агента её проект не разблокирует.
5. В созданной и повторно открытой сессии плашка показывает папку и имя проекта как обычный текст. Для диалога без проекта сохраняется подпись «Без проекта». Название самой сессии и её меню остаются отдельным элементом рядом. На Android при нехватке ширины плашка занимает строку под названием.

## Состояния и платформы

| Состояние | Что видит и может сделать пользователь |
| --- | --- |
| Список загружается | В области списка — «Загрузка проектов…». Плашка сохраняет текущий выбор. |
| Знакомых проектов нет | Сразу доступны «Без проекта» и «Открыть папку…». |
| Список не загрузился | В меню — «Не удалось загрузить проекты» и «Повторить». Черновик сохраняется. |
| Нет доступа к выбранной папке | У плашки — «Нет доступа к папке» и «Выбрать другую…». Прежний проект остаётся выбранным. |
| Сессия создана | Плашка сохраняет контраст. У неё нет шеврона, реакции на наведение или остановки Tab. Диктор читает «Проект, Дизайн-система». |

На Windows и macOS список открывается под плашкой. Стрелки перемещают выбор, Enter подтверждает, Escape закрывает и возвращает фокус на плашку. На Android проекты открываются нижним листом с целями от 48 dp, Back закрывает лист. Выбор новой папки передаётся платформенному диалогу выбора каталога.

В прототипе «Открыть папку…» ведёт к примеру системного выбора каталога. Подтверждение подставляет «Редакция», отмена возвращает прежний проект. Отправка черновика «Сверь отступы в шапке.» проходит через состояние создания. В сохранённом диалоге текст переходит в ленту, а у плашки проекта исчезает действие выбора. Доступ к файлам, отправка на сервер и платформенная клавиатура проверяются в приложении.

## Базовый Desktop

По снимку Windows от оператора восстановлен диалог «Единая модель сессий», выбранный в проекте Heartbeat. В шапке видны «Субагенты · 1», Claude Code, Sonnet 4.5, «Рассуждение: среднее», «Запись в рабочей области», контекст 61% и окно 5 ч. Под параметрами — предупреждение о восстановлении диалогов. В ленте сохранены реплики 14:06–14:12, подписи времени и перекрытие верхнего ответа шапкой. Этот кадр показывает установленное приложение. Новое поведение плашки показано на странице выбора проекта. ### Сверка текста с Windows

В рабочем кадре и в компоненте «Desktop · Основа диалога» названия проектов и сессий привязаны к текстовому стилю «Действие» и переменной `aurora/ink` со значением `#20232A`. Это соответствует `HbTypography.Label` и `AuroraColors.DesktopInk` в Compose. Гарнитура Segoe UI Regular, кегль 14, высота строки 20, межбуквенный интервал 0. Заголовок диалога использует роль `PaneTitle` 15/20, текст сообщения 15/22, время 12/16. Для длинных названий сессий применена альфа-маска шириной 24, как в приложении. [Компонент в Figma](https://www.figma.com/design/ivLmgulIBIkMzOw8sgvKxj/Aurora-DS?node-id=348-178064) · [Реализация панели](https://github.com/aequicor/Heartbeat-v2/blob/aeb38c9b022b0bcd4219968af40852a809842fb1/features/ai-studio/ui/compose/src/commonMain/kotlin/io/github/aequicor/heartbeat/features/aistudio/ui/components/AuroraDesktopSidebar.kt) · [Шкала текста](https://github.com/aequicor/Heartbeat-v2/blob/aeb38c9b022b0bcd4219968af40852a809842fb1/designsystem/foundation/src/commonMain/kotlin/io/github/aequicor/heartbeat/designsystem/foundation/HbTypeScale.kt).

Растровая проверка при масштабе 1× по второму снимку оператора. Измерен видимый текст на белом фоне при одинаковом пороге яркости 180/255. Для Heartbeat границы в Figma и Windows совпали — 60 × 10 px. Для «Архитектура движка» получилось 131 × 13 и 129 × 13, для «Автотесты для очереди» — 149 × 13 и 148 × 13 соответственно. На снимке Windows по контурам букв видны цветные субпиксели. В экспорте Figma сглаживание отличается.
