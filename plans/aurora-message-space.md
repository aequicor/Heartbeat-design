# Aurora: алгоритмы компактного размещения сообщений

14 ноября 2026. Согласованные алгоритмы применены к статическому макету [aurora-new-chat.pen](../aurora-new-chat.pen). Оператор уточнил: короткие ответы агента сжимаются по содержимому; время никогда не увеличивает ширину сообщения и при нехватке места переносится в футер. Реализация в Compose остаётся отдельным этапом.

## Основание и границы

На первом приложенном изображении время находится в отдельной строке слева, хотя справа от «новый запрос.» визуально достаточно места. Второй и третий примеры показывают желаемый принцип: метаданные занимают свободную часть последней строки. Это наблюдение по изображениям, а не описание внутреннего алгоритма Telegram. Точные размеры по растровым примерам не назначаются.

Применяется к Aurora на desktop Windows/macOS и Android: чтение обычных сообщений, финальных ответов, подписей к вложениям, ошибок, генерация и изменение размеров окна. Для пустой истории уплотнять нечего. Глобальные панели и composer сохраняют существующие правила.

Приоритет исходных решений: последнее уточнение в [плане ошибок и меню](aurora-message-error.md#итог-меню-вне-геометрии-сообщения) выше исторических правил [футеров](aurora-message-footers.md). Действия сообщения находятся во внешнем меню, его появление не сужает пузырь и не резервирует полосу. У обычного сообщения остаётся время, у ошибочного — статус и время. Галочки доставки и счётчик просмотров из референсов не добавляются.

## UI/UX-аудит и направление

Аудит по signs из unslop: в доступном фрагменте обнаружено неиспользованное место справа от последней строки и отдельная строка времени, увеличивающая высоту сообщения. Признаки проблем с градиентами, декоративными значками, жирностью и рекламными формулировками не обнаружены. Движение и поведение интерактивных элементов по изображениям не оцениваются. Режим — локальная корректировка компоновки. Метод unslop: Damir Sokolovsky, CC BY 4.0.

1. Продукт: рабочий чат Aurora для чтения ответов и продолжения работы с ними.
2. Характер: спокойный, компактный, точный.
3. Мир: рабочие записи, сообщения и документы Aurora.
4. Моменты: короткий ответ занимает необходимую высоту; длинный сохраняет структуру и ритм чтения.
5. Сигнатура: время завершает сообщение у правого края, используя свободное место последней строки.

Направление согласовано оператором. Этот план заменяет прежние правила размещения времени и ширины коротких завершённых ответов; состав действий и внешнее меню сохраняются.

## 1. Время в последней строке

Сначала сообщение раскладывается обычным способом, без резервирования места под время во всех строках. Затем измеряется время в фактическом шрифте, локали и масштабе. Время остаётся отдельным элементом: пробелы, табуляция и невидимые символы в текст сообщения не добавляются.

Исходные параметры предложения:

| Параметр | Значение |
|---|---|
| Боковые поля пузыря | Существующие 16 dp |
| Верхнее / нижнее поле при inline-времени | 12 / 12 dp; текст не прижат к нижнему краю |
| Верхнее / нижнее поле при отдельном футере | 12 / 4 dp |
| Текст | Существующая роль 16/24 sp |
| Время | Последняя согласованная роль 12/16 sp, muted |
| Минимальный зазор от текста до времени | 8 dp |
| Зазор перед отдельной строкой времени | 4 dp |
| Положение времени | Справа внутри полей пузыря, и у пользователя, и у агента |

Обозначения в одной системе координат внутренней области сообщения:

- `W` — доступная ширина после вычета полей;
- `R` — правая граница занятой области последней строки с учётом смещения её блока;
- `M` — измеренная ширина времени;
- `G` — зазор 8 dp, переведённый в единицы измерителя.

Для обычного LTR-текста предварительное условие: `R + G + M <= W`. Время начинается в `x = W − M`. Его текстовая базовая линия совпадает с базовой линией последней строки. Правый край времени общий для обоих способов размещения.

Проверяется не позиция последнего символа, а геометрия всей последней строки. Ссылки, жирные фрагменты, emoji, inline-объекты и выделенные фоны входят в занятую область. Помимо ширины проверяется прямоугольник времени: он не пересекает содержимое, фон цитаты, hit area ссылки, другие строки и нижние блоки. Если метаданные выше последней строки, высота контейнера считается по объединению границ; компактный вариант выбирается только если он действительно ниже варианта с отдельным временем.

Границы занятого содержимого и времени округляются наружу до физических пикселей, доступная область — внутрь. Равенство допустимо после округления. Это исключает перекрытие из-за дробной плотности. Нельзя смешивать dp, sp и пиксели в одном сравнении.

```text
layoutMessage(content, metadata, constraints, environment):
    width = resolveBubbleWidth(content, constraints)
    body = measureContent(content, width.inner, environment)
    stamp = measureMetadata(metadata, environment)
    fallback = layoutDedicatedMetadataRow(body, stamp, gap = 4dp)

    if metadata is absent:
        return bodyWithNormalPadding(body)
    if content is streaming or message has an error status:
        return layoutStateAccordingToContract(body, stamp)

    tail = findEligibleFinalTextLine(body)
    if tail is absent or tail has unresolved geometry:
        return fallback
    if tail has RTL or mixed bidirectional runs:
        return fallback

    candidate = alignStampToRightAndBaseline(stamp, tail, width.inner)
    if hasGap(tail, candidate, 8dp)
       and noCollision(candidate, body)
       and heightOf(body, candidate) < fallback.height:
        return bodyWithStamp(body, candidate)
    return fallback
```

`findEligibleFinalTextLine` допускает последний обычный абзац, последний пункт списка и подпись после вложения, если после них ничего не отображается. У списка учитывается его локальный отступ. Пустая строка после явного перевода строки не считается свободным местом для уплотнения: авторское форматирование сохраняется.

Если сообщение заканчивается кодом, таблицей, формулой, диаграммой, цитатой с отдельной поверхностью, карточкой файла или изображением без подписи, время остаётся ниже. Время не накладывается на изображение и не внедряется внутрь содержимого файла. Для RTL и смешанного направления первая версия использует отдельную строку справа; поддержка inline потребует отдельной проверки визуальных направлений и доступного порядка чтения.

## 2. Ширина коротких сообщений

Алгоритм размещения времени не расширяет уже разложенный многострочный пузырь только ради удаления футера. Иначе перенос времени может переразложить весь текст и изменить привычную ширину чтения.

Ширина рассчитывается по содержимому без времени: `leftPadding + contentWidth + rightPadding`, с учётом минимальной ширины компонента и пределов доступной области. Только после этого применяется алгоритм 1. Добавлять ширину времени или зазор к ширине пузыря запрещено. Существующие ширины пользовательских сообщений сохранены; расширение ради времени отменено.

Для многострочного пользователя сохраняется существующий расчёт ширины по содержимому и максимум 520 dp. Короткий завершённый ответ агента из одного обычного абзаца сжимается по ширине текста и полей. В макете «Да. Черновик сохранён.»: текст 181, поля 32, округление до 216 dp; время не помещается и находится в отдельном футере. Длинные и составные ответы сохраняют пределы 632 dp для обычного ответа и 680 dp для сложного содержимого. Все пределы ограничиваются локальной доступной шириной; поля страницы учитываются до расчёта пузыря. Внешнее меню в этот расчёт не входит.

Ширина не оптимизируется перебором вариантов до минимальной площади. Во время генерации ширина стабильна. После завершения короткий ответ может один раз сжаться по содержимому с сохранением якоря чтения; время не участвует в выборе ширины.

## 3. Интервалы между блоками

Интервал принадлежит паре соседних видимых блоков. Рендерер не складывает нижний margin предыдущего блока, верхний margin следующего и gap контейнера.

1. Построить список отображаемых семантических блоков.
2. Убрать отсутствующие служебные блоки вместе с принадлежащими им отступами: пустое имя агента, отсутствующую подпись или отсутствующие метаданные. Авторские пустые строки и содержимое кода этим шагом не удаляются.
3. Для каждой пары один раз выбрать интервал по существующему контракту: абзацы 12, пункты списка 6, перед разделом 20, после заголовка 8 dp. При конкуренции требований брать больший интервал, а не сумму.
4. В конце добавить либо inline-время без отдельного gap, либо отдельную строку времени с gap 4.
5. Добавить нижнее поле оболочки один раз.

Между связанными сообщениями одной роли сохраняется 8 dp, при смене роли или новом смысловом блоке — 20 dp. Оптимизация не склеивает разные сообщения и не убирает семантические абзацы. Кегль и межстрочный интервал не уменьшаются ради плотности.

## 4. Статус ошибки и другие состояния

| Состояние | Правило |
|---|---|
| Обычное сообщение / завершённый ответ | Inline-время при прохождении алгоритма 1, иначе отдельная строка справа |
| Ошибка отправки | Отдельный футер: статус и info слева, время справа; повтор остаётся в существующем меню |
| Узкий футер ошибки | Измерить статус вместе с полноценной целью info. Если статус, зазор 8 и время не помещаются, время перенести ниже вправо; статус переносится без обрезания |
| Повторная отправка | Использовать существующий статус повторной отправки; сохранить ID, содержимое и вложения, не создавать второй пузырь |
| Генерация / ожидание | Сохранить действующий индикатор процесса. Не добавлять футер времени, если его ещё нет; если время уже есть, держать его отдельно до завершения |
| Завершение генерации | Один раз пересчитать компактное размещение по окончательному содержимому |
| Пустая история | Нет пузыря, времени и пространства под них |
| Вложение без подписи | Время под блоком вложений |
| Вложение с последней подписью | Проверять свободное место последней строки подписи |

На desktop цели соответствуют разрешённой плотности: 32 dp Dense или 40 dp Comfortable; на Android/touch — 48 dp. Визуальный размер значка не используется вместо размера цели. Крупный текст увеличивает высоту: ни время, ни статус, ни кнопки не обрезаются ради компактности.

## 5. Устойчивость генерации и прокрутки

При каждом токене не переключать время между inline и отдельной строкой. Активный ответ сохраняет ширину, выбранную до потока, и правила состояния из таблицы. После завершения возможен один переход в компактный вариант без анимации высоты пузыря.

Перед перераскладкой запомнить стабильный ID первого видимого сообщения и его визуальное смещение; при длинном сообщении — также видимый блок или текстовую позицию внутри него. После перераскладки восстановить якорь. Если пользователь следовал за концом истории, сохранить следование. Если читал выше, не переводить его вниз. Использовать существующее определение «у конца истории», не вводить новый порог.

Изменение ширины панели, системного шрифта, масштаба, локали или текста повторно запускает измерение. Hover, раскрытие внешнего меню и подтверждение копирования геометрию пузыря не пересчитывают.

## 6. Стоимость измерений и доступность

Использовать результат уже выполненной раскладки текста. Проверка размещения времени получает последнюю строку из этих данных; она не измеряет сообщение посимвольно и не перебирает все ширины. Проверка возможных пересечений ограничивается нижними блоками, попадающими в вертикальный диапазон времени. Если движок не отдаёт надёжные границы, использовать отдельную строку.

Ключ кеша геометрии: ID и версия содержимого, ширина области, параметры шрифта и его фактическая версия, системный масштаб, плотность/DPI, локаль, направление текста, отображаемое время и состояние сообщения. Изменение размеров вложения тоже инвалидирует запись. Кеш ограничен по объёму, история остаётся виртуализированной.

Время остаётся одним узлом метаданных после содержимого в доступном порядке чтения; визуальное перемещение не создаёт дубль. Копирование текста не захватывает искусственные пробелы или время. Выделение текста и касания ссылок не пересекаются с метаданными. Неизвестное время не подменяется текущими часами.

## Проверка алгоритмов

| Проверка | Ожидаемый результат |
|---|---|
| Сообщение с первого изображения | При фактическом наличии места `14:03` справа на строке «новый запрос.» |
| Условные измерения: W=320, R=220, M=36, G=8 | 264 ≤ 320: inline, если нет других пересечений |
| W=320, R=276, M=36, G=8 | Ровно помещается после округления: inline |
| W=320, R=277, M=36, G=8 | Не помещается: отдельная строка |
| Одно слово / одна строка любой роли | Ширина по содержимому и полям, без добавления времени; при нехватке места время в футере |
| Очень длинная ссылка или слово | Обычный перенос по правилам текста; время не перекрывает последнюю строку |
| Жирный текст, emoji, последний пункт списка | Проверка реальной геометрии с локальным смещением |
| Явный завершающий перевод строки | Форматирование сохраняется, время отдельно |
| RTL / смешанный текст | Отдельная строка времени без перекрытий |
| Код, таблица, формула или файл в конце | Время отдельно; локальная прокрутка содержимого сохранена |
| Масштаб 100%, 150%, 200%; окна 320, 390, 720, 1440 | Измерение заново; обычный текст без горизонтального overflow |
| Ошибка, длинный перевод статуса | Статус и info доступны, время переносится при нехватке места |
| Генерация и завершение | Нет переключений inline/footer на каждом токене, якорь чтения сохранён |
| Открытие меню | Ширина и высота сообщения неизменны |

Это критерии для реализации, а не отчёт о пройденных runtime-тестах. Числа в трёх арифметических примерах — условные измерения в одной системе координат.

## Результат в Pencil

Обновлены исходные сообщения и переопределения связанных экземпляров, включая Android. Порядок проходов: отступы, проверка существующих цветов и иконок, сохранение текста и типографики, размещение времени, привязка внешних меню. Время не добавляет ширину; источник короткого ответа агента `o6ONZ` сжат до 216 dp. Внешние меню перепривязаны к фактическим размерам сообщений.

- Лист 50 `C04Uv`: обычные сообщения до/после, нехватка места, короткие реплики обеих ролей. Основной Android-пример: 168 → 156 dp при неизменной ширине 338 dp. Экономия 12 dp учитывает симметричные поля 12/12 у inline-варианта.
- Лист 51 `ExZDB`: документ с короткой подписью, длинной подписью, без подписи и Android. Время не накладывается на файловый блок.
- Лист 52 `CcQKk`: ошибка desktop, Android, узкая область 224 dp и успешный повтор. В узкой области время ниже статуса, цель info 48 dp сохранена.
- Лист 53 `QOEUX`: фиксированные контрольные ширины 184/180 dp для проверки зазора, статический срез генерации и текст 200%. Эти контрольные ширины не вычисляются из времени. Пустая история и загрузка сохраняют исходные экраны 05/06.

Четыре листа проверены по границам видимого содержимого: неожиданных обрезаний нет. Обычные сообщения, вложения и ошибки проверены визуально. Шрифт измерялся средствами Pencil; абсолютное положение времени в статических образцах не является работающим адаптивным алгоритмом. Системный fontScale, генерация, выделение, касания и сохранение якоря требуют проверки в Compose Multiplatform.

Локальные превью: `exports/message-space/`. Публикация через PR фиксируется после сохранения макета; SHA для обновления подмодуля выдаётся только после слияния.

## Полный аудит всех экранов

14 ноября 2026, по отдельному запросу оператора проверен весь документ с раскрытием компонентных экземпляров, включая скрытые источники и контрольные образцы. Направление и сценарий не изменялись. Машиночитаемые измерения: [aurora-message-space-audit.json](checks/aurora-message-space-audit.json).

- Просмотрено 60 верхнеуровневых кадров, в том числе служебные и не содержащие сообщений. Обнаружены 1122 экземпляра времени и два состояния «Отправка…». Повторения в масках истории считаются отдельными экземплярами, а не отдельными пользовательскими сообщениями.
- По разрешённому содержимому, стилям и геометрии выделено 78 различных компоновок: 34 со временем в строке, 44 с отдельным футером. Проверены все группы, а не выборка экранов.
- Ширина пузыря не изменилась при отключении футера. Для каждого варианта измерены границы времени, последняя строка и зазор; итог — 0 пересечений, 0 выходов за внутренние границы и 0 зависимостей ширины от футера. Минимальный измеренный зазор в строке — 8 dp.
- Отдельный проход по цепочкам clipping-контейнеров: 93 видимых пересечения отметок времени с областями просмотра, горизонтальных обрезаний нет. Вертикальная маска/прокрутка истории не считается нарушением.

Исправлены четыре экземпляра в двух старых узких контрольных образцах `X8zoB` и `HbtNh`: у пользователя футер имел лишнюю высоту 48 вместо 16, у агента время сохраняло координаты более широкой строки. На ширине пузыря 288 dp агентское время теперь в футере. Образец `HbtNh`, подписанный «200%», действительно приведён к тексту 32/48 и времени 24/32; зазор и перенос проверены заново.

В Android-состояниях текущего этапа и финала возвращены уже существовавшие, но отключённые отметки времени пользовательских сообщений (`D2nc9z`, `Y2ys1` и их экранные экземпляры). Один оставшийся короткий ответ агента `pe1Wv` сжат с 632 до 612 dp по тексту и полям; время остаётся в футере. Внешние меню перепривязаны к новым размерам.

Визуально проверены основной Android-чат, Android текущего этапа и финала, узкий контроль 320, контроль 200% и длинная desktop-история. Проверка относится к сохранённым статическим размерам Pencil. Автоматическое поведение при произвольной ширине, платформенные шрифты и системный fontScale необходимо проверять в Compose.
